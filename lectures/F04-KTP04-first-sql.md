# Пара Ф04 КТП04
## Первое знакомство с SQL

Ф04 — фактическая пара №4 по рабочему плану. КТП04 — опорная позиция исходного КТП. Вводные элементы работы со средой и SQL относятся также к темам КТП11, КТП12, КТП16 и КТП17.

Всем привет! Вы уже видели pgAdmin и создавали таблицы через его окна. Сегодня начнём записывать действия с базой данных в виде команд SQL. Создадим маленький каталог учебных курсов, добавим записи и получим их на экране. Все действия выполним последовательно и сохраним в одном файле.

Представьте, что учебный центр предлагает несколько курсов. Для каждого требуется хранить номер, название и продолжительность. Сначала определим, что должна содержать одна запись. Затем опишем структуру таблицы, внесём данные и проверим результат. К концу работы вы сможете самостоятельно повторить этот маршрут для новой записи.

## Вспоминаем устройство таблицы

Посмотрите на будущий каталог:

| course_id | title | duration_hours |
| --- | --- | --- |
| 1 | Основы Python | 24 |
| 2 | Веб-дизайн | 18 |
| 3 | Робототехника | 30 |

Каждая строка описывает один курс. Столбец course_id содержит его номер, title — название, duration_hours — продолжительность в учебных часах. Число 24 относится к курсу «Основы Python», поскольку находится в той же строке.

Ответьте на вопросы. Сколько в примере курсов? Сколько атрибутов описывает каждый курс? Где будет храниться название четвёртого курса? В таблице три строки и три столбца. Для нового курса понадобится ещё одна строка с тем же составом полей.

Назовём курс сущностью нашей предметной области. Конкретный курс «Основы Python» с номером 1 — экземпляр этой сущности. Название и продолжительность — его атрибуты. В реляционной модели сведения такого вида представляются отношением; на практике мы будем работать с таблицей. Одну её строку также называют кортежем.

Эти термины описывают уже знакомые элементы. Покажите в примере один кортеж и значение выбранного атрибута. Затем объясните, что изменится при добавлении нового курса. Строк станет больше, набор столбцов останется прежним.

## Кто выполняет наши команды

База данных хранит организованные сведения. PostgreSQL — система управления базами данных, которая принимает команды, проверяет их и выполняет действия. pgAdmin — приложение, через которое мы подключаемся к PostgreSQL, рассматриваем объекты и отправляем запросы.

SQL — язык для описания структуры и работы с данными. В нём есть команды создания таблиц, добавления строк, получения результатов и других действий. Сегодня будем возвращаться к трём основным конструкциям: создать структуру, добавить данные, получить выборку.

Когда вы нажимали кнопки в окнах создания таблицы, приложение формировало необходимые действия для сервера. Теперь мы запишем команды самостоятельно. Сохранённый текст позволит повторить работу в другой подготовленной учебной базе и увидеть последовательность выполненных шагов.

Вопрос к классу: где появятся данные после сохранения SQL-файла на рабочем столе? Сам файл содержит текст команд. Изменения в базе происходят после их отправки серверу. Поэтому после каждого выполненного действия будем проверять результат и отдельно сохранять текст нашей работы.

## Открываем Query Tool

Создайте папку lesson_04. Откройте pgAdmin 4 и найдите слева дерево объектов. В разделе Servers выберите учебный сервер PostgreSQL. Если требуется подключение, используйте выданные вам параметры. Пароль вводится в окно подключения.

Раскройте Databases и выберите свою учебную базу. Её название указывает преподаватель. Внутри базы находятся схемы, а внутри схем — таблицы. Для сегодняшнего примера используем подготовленную рабочую область своей базы.

Нажмите правой кнопкой мыши на выбранную базу и откройте Query Tool. В верхней части окна находится редактор SQL. Ниже расположены вкладки с результатами и сообщениями. Data Output показывает табличный результат, Messages — сведения о выполнении и ошибках.

Важно! Перед началом проверьте название базы в подключении Query Tool. Открытые окна могут относиться к разным базам. Выполняйте задания в своей учебной базе, чтобы результат каждой команды относился к вашему примеру.

Найдите кнопку выполнения SQL и посмотрите её всплывающую подсказку. Сначала будем запускать по одному выделенному фрагменту. Выделение должно включать всю команду от первого слова до завершающей точки с запятой. Если выделения нет, действие кнопки может относиться ко всему тексту редактора в зависимости от выбранного режима выполнения.

Для сегодняшних упражнений используйте включённый Auto commit в Query Tool: выполненные изменения будут подтверждаться автоматически. Сохраните содержимое редактора через Save в файл lesson04.sql внутри созданной папки. По мере работы будем дописывать команды в этот файл. Параметры подключения и пароли в него не добавляются.

## Получаем первый ответ от сервера

Введите короткую команду:

```sql
SELECT 2 + 3;
```

Выделите её целиком и выполните. В Data Output должен появиться результат 5. Конструкция `SELECT` позволяет получить результат выражения или выборки. В первом опыте PostgreSQL вычислил арифметическое выражение и вернул ответ.

Посмотрите на точку с запятой. Она завершает SQL-команду. При последовательной записи нескольких команд это помогает определить их границы. Перенос строки делает текст удобным для чтения; команду мы завершаем явно.

Самостоятельно измените числа в этой же команде, предскажите ответ и выполните выбранное выражение. Например, можно получить сумму 7 и 4. Убедитесь, что видите собственный ожидаемый результат. После опыта оставьте в файле один выбранный вариант команды.

Если ответа нет, проверьте, что выделили команду целиком, выбрали выполнение SQL и подключены к серверу. Загляните в Messages. Сообщение об ошибке помогает определить, какое действие сервер не смог выполнить.

## Выбираем поля и типы данных

Вернёмся к каталогу курсов. Назовём таблицу lesson04_courses. Такое имя связывает её с сегодняшним упражнением. Для трёх столбцов используем латинские имена с подчёркиваниями: course_id, title и duration_hours.

Выберем типы значений. Номер курса и продолжительность задаются целыми числами. Для них подойдёт integer. Название задаётся текстом, для него используем text.

Тип данных определяет, какие значения могут храниться в столбце и какие действия имеют смысл. Продолжительность 24 записана числом и подходит для арифметических вычислений. Название «Основы Python» хранится как текст. Числовой вид телефонного номера, например, ещё не делает его величиной для сложения; тип выбирают по назначению атрибута.

Справка! Домен атрибута описывает допустимую область значений и их смысл. Для продолжительности курса в реальной системе потребуются дополнительные правила, например положительное значение. На текущем шаге задаём тип integer; ограничения по смыслу будем последовательно добавлять на следующих занятиях.

В course_id будем вручную указывать разные номера: 1, 2, 3 и далее. Правило уникальности идентификатора позднее закрепим средствами базы. Сейчас следите за значениями самостоятельно и объясняйте, какой курс обозначает каждый номер.

## Создаём таблицу командой

Допишите в lesson04.sql следующее определение:

```sql
CREATE TABLE lesson04_courses (
    course_id integer,
    title text,
    duration_hours integer
);
```

Прочитаем его по частям. `CREATE TABLE` создаёт новую таблицу. После этих слов указано её имя. В круглых скобках перечислены поля: сначала имя, затем тип. Запятые отделяют определения друг от друга. После последнего поля запятая не ставится. Закрывающая скобка завершает описание полей, точка с запятой — команду.

Напишите этот фрагмент самостоятельно, затем сравните имена и знаки с образцом. Выполните только выделенное определение таблицы. В Messages должно появиться подтверждение успешного выполнения. Табличная выборка данных в этот момент не требуется: команда описывает структуру нового объекта.

Обновите список таблиц через Refresh в своей рабочей схеме. Найдите lesson04_courses и её столбцы. Сопоставьте их с текстом команды. Должны присутствовать course_id и duration_hours типа integer, а также title типа text.

Вопрос к классу: сколько курсов уже хранится после создания таблицы? Пока ни одного. Мы подготовили структуру для будущих строк. Описание полей существует даже у пустой таблицы.

## Читаем пустую таблицу

Добавьте следующую команду:

```sql
SELECT * FROM lesson04_courses;
```

Знакомое SELECT получает данные. Звёздочка означает все столбцы, `FROM` указывает таблицу, из которой они берутся. Выполните эту команду отдельно. В результате появятся названия столбцов без строк с курсами.

Пустой результат здесь ожидаем. Сравните его с первым опытом SELECT 2 + 3. Там вычислялось выражение. Сейчас запрос читает существующую таблицу, в которой ещё нет записей. По названиям столбцов можно убедиться, что структура создана правильно.

Важно! Первое создание таблицы выполняем один раз. Для просмотра её содержимого можно повторять SELECT. Если повторно выполнить CREATE TABLE с тем же именем в той же схеме, PostgreSQL сообщит, что объект уже существует. В этом случае проверьте имеющуюся таблицу выборкой и продолжите с нужного шага.

## Добавляем первую запись

Допишите команду добавления курса:

```sql
INSERT INTO lesson04_courses (course_id, title, duration_hours)
VALUES (1, 'Основы Python', 24);
```

`INSERT INTO` добавляет данные в указанную таблицу. Список полей задаёт порядок значений. Конструкция `VALUES` содержит эти значения: номер 1, название «Основы Python», продолжительность 24.

Обратите внимание на одинарные кавычки вокруг текста. Они обозначают текстовое значение. Числа в этом примере записаны без кавычек. Имена таблицы и полей записаны теми же буквами, что и при создании структуры.

Выполните вставку один раз. Затем вернитесь к уже сохранённому SELECT * FROM lesson04_courses и запустите только эту выборку. В таблице должна появиться одна строка. Проверьте все три значения и прочитайте получившуюся запись вслух.

Справка! Положение значения в VALUES соответствует положению поля в списке INSERT. Для course_id, title, duration_hours используются именно номер, название и продолжительность. Такой явный список помогает читать команду и проверять соответствие данных.

Вопрос к классу: где окажется число 24? В duration_hours. Что должно измениться в команде для курса с номером 2? Потребуются новые значения в VALUES. Название таблицы и набор полей сохранятся.

## Добавляем ещё два курса

В одном INSERT можно перечислить несколько строк:

```sql
INSERT INTO lesson04_courses (course_id, title, duration_hours)
VALUES
    (2, 'Веб-дизайн', 18),
    (3, 'Робототехника', 30);
```

Каждая пара круглых скобок содержит значения отдельной записи. Запятая между такими группами отделяет строки. Точка с запятой завершает всю команду после последней записи.

До запуска запишите ожидаемое количество строк. Одна уже существует, две добавятся, всего получится три. Выполните выделенный INSERT один раз. Затем снова запустите сохранённую выборку всех столбцов и сопоставьте результат с каталогом в начале занятия.

Проверьте состав записей: номер 1 и «Основы Python», номер 2 и «Веб-дизайн», номер 3 и «Робототехника». Порядок строк на экране может различаться. Правила сортировки будем разбирать отдельно; сейчас сверяем сами записи и соответствие значений столбцам.

Важно! Повторное выполнение INSERT снова пытается добавить указанные строки. В нашей первой таблице уникальность номеров ещё не настроена, поэтому возможно появление одинаковых записей. Перед запуском выделяйте нужную команду и проверяйте, что собираетесь выполнить. Для просмотра результата запускайте SELECT.

## Выбираем нужные столбцы

Допустим, сейчас нужен список номеров и названий курсов. Перечислим эти поля явно:

```sql
SELECT course_id, title FROM lesson04_courses;
```

В Data Output должны появиться два столбца. Продолжительность продолжает храниться в таблице. Состав результата определяется перечнем полей после SELECT.

Самостоятельно измените эту команду так, чтобы получить название и продолжительность. Затем составьте выборку только одного столбца title. Перед каждым запуском назовите ожидаемые столбцы результата. Проверьте, что запрос показывает нужные сведения о тех же трёх курсах.

Сравните три действия сегодняшней работы. CREATE TABLE подготовил структуру. INSERT INTO сохранил новые записи. SELECT прочитал данные и вернул результат. Эти команды могут находиться в одном файле; каждая выполняет своё действие после запуска на сервере.

## Разбираем сообщения и исправляем ошибки

Если появилась ошибка синтаксиса, сначала посмотрите, какое место указано в Messages. Проверьте запятые между полями, закрывающую скобку и одинарные кавычки у текста. Сопоставьте команду с образцом по частям, сохраняя собственные названия и значения.

Если сервер сообщает, что таблица не существует, сравните написание lesson04_courses в CREATE TABLE и запросе. Затем проверьте подключение: таблица могла быть создана в другой базе. Сообщение о том, что таблица уже существует, обычно связано с повторным запуском её создания.

Если ошибка относится к integer, посмотрите значение для соответствующего поля. Слова с описанием продолжительности должны быть преобразованы к принятому числовому представлению: в duration_hours мы записываем число часов. Например, для 24 часов используем целое число 24.

Если названия столбцов в SELECT написаны иначе, чем в определении таблицы, исправьте имена. В нашем примере duration_hours состоит из двух английских слов с подчёркиванием. Имена в командах должны соответствовать созданной структуре.

Если строк оказалось больше ожидаемого, посмотрите, какие INSERT вы запускали повторно. Одинаковые строки могли добавиться ещё раз. Покажите текущее состояние, определите причину и согласуйте восстановление исходного набора в учебной базе. Команды изменения и удаления данных разберём в дальнейших занятиях.

Команду завершает точка с запятой. Звёздочка выбирает все столбцы. Для названий перечисляем title после SELECT. Новую запись проверяем выборкой и сопоставлением состава строк до и после вставки.

Подготовьтесь без подсказки изменить пример INSERT для ещё одного курса и составить SELECT двух выбранных полей. На следующем занятии продолжим создавать таблицы и разберём, как база обеспечивает уникальность идентификатора.
