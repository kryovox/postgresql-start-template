В Query Tool оставьте Auto commit включённым. Намеренные ошибки в конце материала запускайте по одной. Сохраняйте их текст и объяснение в report.md. На этапе самостоятельной работы используйте отдельную таблицу movies в той же учебной базе.

## От SQL файла к результату

PostgreSQL — система управления базами данных. Её сервер выполняет команды и хранит таблицы. pgAdmin 4 — клиентская программа для подключения к серверу. SQL — язык, на котором описываются структура и действия с данными.

SQL-файл хранит текст команд на компьютере. После сохранения выполните нужный фрагмент в Query Tool. В Data Output появятся строки результата, в Messages — сообщения сервера. Данные сохраняются в подключённой базе PostgreSQL.

Откройте базу через Servers → Databases, нажмите на неё правой кнопкой и выберите Query Tool. Проверьте подключение простым выражением:

```sql
SELECT 2 + 3;
```

Ожидаемый результат — число 5. SELECT получает результат запроса. Завершённая команда заканчивается точкой с запятой. Текстовые значения записываются в одинарных кавычках: 'Ноутбук'. Для десятичного числа используйте точку: 1500.50.

Ключевые слова пишем заглавными буквами, имена таблиц и столбцов — строчными латинскими буквами с подчёркиваниями. В нашем стиле product_id и release_year обозначают составные имена. Комментарий, начинающийся с двух дефисов, поясняет команду до конца строки.

Сохраняйте команды с короткими комментариями о назначении и результате. При отсутствии выделения редактор может выполнить весь открытый текст, поэтому проверяйте выбранный фрагмент перед запуском.

## Отношение кортеж атрибут и домен

Будущая таблица магазина содержит следующие сведения:

| product_id | title | price | quantity |
| --- | --- | --- | --- |
| 1 | Ноутбук | 50000.00 | 5 |
| 2 | Мышь | 1500.00 | 10 |
| 3 | Клавиатура | 3000.00 | 0 |

Одна строка описывает один товар. Четыре столбца задают идентификатор, название, цену и остаток. Значения одной строки относятся к одному объекту.

| Понятие | В примере | Смысл |
| --- | --- | --- |
| Отношение relation | Таблица products | Набор записей с общей структурой |
| Кортеж tuple | Строка про ноутбук | Значения атрибутов одного товара |
| Атрибут attribute | Столбец quantity | Свойство товара |
| Домен domain | Допустимые значения quantity | Целые числа от нуля и выше |

Домен определяет допустимые значения атрибута. Остаток может быть равен 0, 5 или 10. Число −3 нарушает правило магазина, а слово «пять» не преобразуется к выбранному целочисленному типу. В SQL типы и ограничения помогают закрепить такие правила.

В математическом отношении одинаковые кортежи не повторяются. SQL-таблица без подходящих ограничений допускает повторяющиеся строки. В нашей таблице различимость записей обеспечит первичный ключ. Порядок строк обычной выборки заранее не гарантируется; сверяйте значения товаров.

Мини практика. Укажите число кортежей и атрибутов в примере. Назовите домен остатка и предложите допустимое и недопустимое значения. Запишите объяснение в отчёте.

## Схема и состояние данных

Схема отношения описывает имя таблицы, её столбцы, типы и ограничения. Состояние отношения, instance, — набор строк в определённый момент. Пустая таблица уже имеет схему. После добавления товара её состояние изменяется.

В дереве pgAdmin слово schema обозначает также пространство имён PostgreSQL, например public. В понятиях schema/instance нас интересуют описание структуры таблицы и её текущее содержимое.

Определите, что изменится в каждом случае: в магазин добавили товар; обновили цену ноутбука; в описание таблицы добавили столбец цвета. Сохраните ответы и объясните их своими словами.

## Типы данных и первичный ключ

Для товаров используем integer, text и numeric(10, 2). integer хранит целые числа, text — текст, numeric(10, 2) — точные десятичные числа с десятью цифрами всего и двумя после точки. Цена записывается с точностью до копеек; PostgreSQL приводит значение к заданному масштабу.

Первичный ключ PRIMARY KEY позволяет однозначно выбрать строку. Его значения уникальны и обязательно присутствуют. В products таким столбцом станет product_id. Названия разных товаров могут совпадать.

GENERATED BY DEFAULT AS IDENTITY поручает PostgreSQL автоматически выдавать идентификаторы из последовательности при пропуске product_id во вставке. PRIMARY KEY проверяет уникальность. BY DEFAULT допускает и явно переданный номер; для обычных вставок используйте автоматическую выдачу.

После удаления или неудачной вставки номера могут иметь пропуски. Явная вставка числа не подстраивает последовательность под него. Количество строк проверяйте по результату SELECT.

## Создание таблицы

Команды описания структуры относятся к DDL, Data Definition Language. CREATE TABLE создаёт новую таблицу. Запишите и выполните определение:

```sql
CREATE TABLE products (
    product_id integer GENERATED BY DEFAULT AS IDENTITY
        PRIMARY KEY,
    title text NOT NULL,
    price numeric(10, 2) CHECK (price >= 0),
    quantity integer NOT NULL DEFAULT 0
        CHECK (quantity >= 0)
);
```

В скобках перечислены имена столбцов, типы и правила. Запятые разделяют определения, после последнего запятая не ставится. NOT NULL делает значение обязательным. CHECK задаёт условие допустимости. DEFAULT 0 подставляет ноль, когда quantity пропущен во вставке или явно запрошено значение по умолчанию.

price допускает отсутствие значения: карточка товара может появиться до согласования цены. quantity обязателен и должен быть неотрицательным целым. Название обязательно, однако NOT NULL само по себе допускает пустой текст ''.

Обновите список Schemas → public → Tables через Refresh и найдите products. При другой учебной схеме используйте её список таблиц. Затем прочитайте созданную таблицу:

```sql
SELECT * FROM products;
```

Звёздочка выбирает все столбцы, FROM указывает таблицу. Сейчас результат содержит заголовки без строк. CREATE TABLE с тем же именем повторно сообщит о существующем объекте.

Проверка понимания. Покажите в определении имя таблицы, первичный ключ, обязательные поля, значение по умолчанию и условия допустимости. Объясните, какие данные уже существуют после одного CREATE TABLE.

## Добавление и чтение данных

Команды добавления, изменения и удаления относятся к DML, Data Manipulation Language. Для добавления используется INSERT INTO. Первая строка товара:

```sql
INSERT INTO products (title, price, quantity)
VALUES ('Ноутбук', 50000, 5);
```

Список полей задаёт порядок значений в VALUES. product_id пропущен и назначается автоматически. Выполните вставку один раз, затем прочитайте таблицу. Добавим ещё две строки:

```sql
INSERT INTO products (title, price, quantity)
VALUES
    ('Мышь', 1500, 10),
    ('Клавиатура', 3000, 0);
```

При последовательном первом выполнении должно получиться три товара. Повторный INSERT снова добавит данные, поэтому для проверки выполняйте SELECT. Выберите отдельные столбцы:

```sql
SELECT product_id, title, price FROM products;
```

quantity продолжает храниться в таблице. Самостоятельно получите title и quantity. Перед выполнением назовите ожидаемые столбцы результата. SELECT часто выделяют в отдельную группу DQL; в других классификациях его относят к DML. Здесь его задача — чтение данных.

## NULL и условия отбора

NULL отмечает отсутствие известного значения. У price договоримся понимать его как «цена ещё не согласована». Цена 0 означает известную нулевую цену. Пустая строка '' является текстовым значением длины ноль.

Добавьте товар с неизвестной ценой:

```sql
INSERT INTO products (title, price)
VALUES ('Коврик', NULL);
```

Ожидаются четыре товара. Для коврика quantity получит DEFAULT 0. Явный NULL в quantity был бы отклонён через NOT NULL: значение по умолчанию не заменяет явно переданный NULL.

Найдите товары с неизвестной ценой:

```sql
SELECT product_id, title FROM products
WHERE price IS NULL;
```

WHERE задаёт условие отбора, IS NULL проверяет отсутствие известного значения. Для известных цен используйте IS NOT NULL. Выполните также следующий опыт:

```sql
SELECT product_id, title FROM products
WHERE price = NULL;
```

Обычное сравнение с NULL даёт неизвестный логический результат. WHERE оставляет строки с истинным условием, поэтому этот запрос не найдёт коврик. Запишите, какое условие подходит для проверки неизвестной цены.

Для выбора конкретного товара используйте первичный ключ:

```sql
SELECT product_id, title, price FROM products
WHERE product_id = 1;
```

При исходном порядке вставок это ноутбук. Всегда проверяйте фактический идентификатор нужной строки. Найдём товары дешевле 2000:

```sql
SELECT product_id, title, price FROM products
WHERE price < 2000;
```

Ожидается мышь. Для коврика сравнение неизвестной цены с числом даёт неизвестный результат, поэтому он не попадает в эту выборку.

## Изменение данных

Перед изменением прочитайте нужную строку тем же условием WHERE. Убедитесь, что product_id = 1 соответствует ноутбуку. Затем выполните:

```sql
UPDATE products
SET price = 55000
WHERE product_id = 1;
```

UPDATE указывает таблицу, SET задаёт новое значение. Повторная выборка ноутбука должна показать цену 55000.00. Название, идентификатор и остаток сохраняются.

Отдельный опыт относится ко всем четырём товарам. Сначала получите их остатки, затем увеличьте каждый на единицу:

```sql
UPDATE products
SET quantity = quantity + 1;
```

При исходных остатках 5, 10, 0 и 0 получатся 6, 11, 1 и 1. WHERE здесь пропущен осознанно: действие применяется ко всем строкам.

Важно! UPDATE без WHERE изменяет все строки таблицы. Перед адресным изменением выполняйте предварительный SELECT с тем же условием. В Auto commit успешная команда сохраняется; отмена текста в редакторе не восстанавливает изменённые данные базы.

## Удаление данных

Сначала прочитайте товары с price < 2000. Убедитесь, что выбрана мышь, затем примените то же условие:

```sql
DELETE FROM products
WHERE price < 2000;
```

При исходной последовательности останутся ноутбук, клавиатура и коврик. Повторите выборку по условию и прочитайте все данные. Структура таблицы сохраняется.

Для адресного удаления прочитайте коврик по его идентификатору. При первом последовательном выполнении до проверочных ошибок это номер 4. Затем удалите эту строку:

```sql
DELETE FROM products
WHERE product_id = 4;
```

Проверьте таблицу: должны остаться ноутбук с остатком 6 и клавиатура с остатком 1. Если ваши номера отличаются, используйте проверенный фактический product_id.

Важно! DELETE без WHERE удаляет все строки таблицы. Перед удалением проверяйте подключённую базу и предварительный SELECT. Пустая таблица продолжает существовать. Удаление структуры в эту работу не входит.

## Целостность данных

Целостность — соответствие данных правилам модели. Целостность сущности поддерживается первичным ключом: каждая строка имеет уникальный обязательный идентификатор. Доменная целостность связана с типами, обязательностью и допустимыми значениями.

Ссылочная целостность описывает согласованность связанных таблиц. Например, указанный для сотрудника отдел должен существовать. Реализацию межтабличных ссылок рассмотрим в следующих занятиях; сейчас используем только первичный ключ.

CHECK отклоняет значение, когда его условие ложно. Для price = NULL проверка price >= 0 имеет неизвестный результат, который CHECK допускает. Обязательность значения задаётся отдельно через NOT NULL.

## Памятка по запуску

Проверьте учебную базу, откройте Query Tool и main.sql, сохраните изменения, выделите нужную команду и выполните её. После SELECT читайте Data Output, после изменения данных выполняйте проверочную выборку. При ошибке начните с Messages: сопоставьте имя таблицы, столбцы, типы, кавычки и знаки.

Если личного репозитория ещё нет, создайте копию [шаблона курса](https://github.com/kryovox/postgresql-start-template) через Use this template → Create a new repository и клонируйте её. Дальнейшую работу выполняйте в своей копии.
